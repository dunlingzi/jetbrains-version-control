# JGC 国际化（i18n）接入设计

- 日期：2026-10-08
- 状态：brainstorm 两轮确认，待实施计划
- 范围：UI 文案国际化，覆盖 manifest / 扩展主机 / webview 三层
- 首批语言：英文（源码默认，零变化）+ 简体中文

## 1. 背景与目标

现状（已侦察确认）：三层用户可见文案全部硬编码英文，无任何 i18n 机制——

- `package.json` contributes：18 个命令 title、2 个视图容器、3 个视图名、9 个配置项（description / enumDescriptions），无 `%key%` 占位
- 扩展主机 `src/`：39 处 `show*` 对话框调用（extension.ts 35 + blameManager.ts 4）、状态栏 text/tooltip、git 用户可见错误
- Webview `webview/src/`：45 个 `.tsx`、7 个 app 共用单包（`main.js`），JSX 文本 / title / placeholder 等全部硬编码

目标：

1. VS Code 显示语言为 `zh-cn` 的用户看到完整中文 UI（含命令面板、设置页、webview、对话框、状态栏）
2. 英文用户零感知变化（源码英文即默认语言，无翻译文件时原样输出）
3. 机器可校验、可持续扩展：新增语言 = 新增翻译文件，零代码改动

## 2. 关键决策（本轮 brainstorm 结论）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 语言切换机制 | **跟随 VS Code 显示语言**。否决插件内独立设置（`jgc.language`）——`vscode.l10n` 机制不支持覆盖，独立设置需自研词典方案，违背生态标准 |
| D2 | 首批语言 | 英文（源码默认）+ 简体中文（`zh-cn`） |
| D3 | 翻译来源 | AI 辅助产出初稿 + 人工审校定稿（交付即可用） |
| D4 | Webview 译文装载 | **方案 A：`vscode.l10n.bundle` 同步注入**（详见 §3.3） |

### 已验证的技术事实（2026-10-08 实测）

| 事实 | 证据 |
|---|---|
| `l10n.bundle` / `l10n.uri` 存在于本项目锁定的 `@types/vscode@^1.85` | `node_modules/@types/vscode/index.d.ts:17038 / 17044` |
| `@vscode/l10n` 的 `config({ contents })` 为**同步**，`({ uri })` 为异步 | 官方 README（microsoft/vscode-l10n） |
| `@vscode/l10n-dev export` 可从 `.ts/.tsx` 提取字符串 | 探测实测：4/4 命中（含 JSX 属性内 `l10n.t()` 调用） |
| 使用 bundle 需在 `package.json` 声明 `"l10n": "./l10n"` | l10n-dev 运行时告警提示 |

## 3. 架构与数据流

### 3.1 三层机制总览

```
package.json (contributes)
  "title": "%jgc.command.refreshLog.title%"        ← %key% 占位符
  翻译源: package.nls.json (en 基线) / package.nls.zh-cn.json
  ↑ VS Code 按用户显示语言自动装配，缺 key 回退英文

扩展主机 src/
  vscode.l10n.t("...")
  翻译源: l10n/bundle.l10n.json (en 基线, l10n-dev 产出, 提交仓库)   ← 单一 bundle
         l10n/bundle.l10n.zh-cn.json (中文翻译)
  ↑ VS Code 启动时自动加载当前语言 → vscode.l10n.bundle

Webview webview/src/
  @vscode/l10n 的 l10n.t("...")
  译文来源: 复用主机侧已加载的 vscode.l10n.bundle
  → src/views/html.ts 注入 → main.tsx 同步 config({ contents })
```

核心设计：**主机与 webview 共用同一份 bundle**。`l10n-dev export` 一次扫描 `./src` + `./webview/src` 产出统一清单；webview 无需独立翻译文件、无需格式转换（`config({ contents })` 与 `l10n.bundle` 是官方 README 指出的配对用法）。

### 3.2 数据流（webview 文本链路）

1. 7 个 app 的 HTML 全部经 `getWebviewHtml()`（`src/views/html.ts`）统一生成——改一处全覆盖
2. `html.ts` 读取 `vscode.l10n.bundle`（当前语言翻译对象；英文环境为 `undefined`）→ `JSON.stringify` 后将 `<` 转义为 `\u003c`（防译文含 `</script>` 截断 HTML）→ 在 `<body>` 内 `main.js` **之前**注入：
   ```html
   <script nonce="${nonce}">window.__L10N_BUNDLE__ = {...};</script>
   ```
   现有 CSP（`script-src 'nonce-...'`）天然允许该 inline script，无需改动
3. `<html lang="en">` 写死值改为 `vscode.env.language`（无障碍 + 字体回退）
4. `main.tsx` 顶部同步执行 `l10n.config({ contents: window.__L10N_BUNDLE__ ?? {} })`，此后所有 `l10n.t()` 立即可用
5. 英文环境：`bundle` 为 `undefined` → 注入 `{}` → `l10n.t()` 原样返回英文源码，**回退天然成立**

约束规则：

- 组件模块**禁止在模块顶层**调用 `l10n.t()`（import 先于 main.tsx 执行，装载顺序不可靠）；所有调用必须在 render / 函数体内
- 语言切换需要 reload window，无需做运行时响应式

### 3.3 方案 A 选型理由（对比 B / C）

- **A（采用）**：`config({ contents })` 同步，零时序问题、零额外请求；bundle 仅含当前语言；现有 nonce CSP 直接兼容。代价仅为 HTML 内嵌几 KB JSON（原 HTML 本来就每次动态生成）
- **B（否决）**：`config({ uri })` 异步，渲染前多一个 await 时序控制点、多一次 fetch、英文时 `uri` undefined 需分支——为省几 KB HTML 换来三类新复杂点
- **C（否决）**：自研 webview 字典（打包各语言 JSON + host 传 locale）。类型安全有吸引力，但引入第二套翻译流程、丢弃 l10n-dev 工具链（提取 / 伪语言 / XLF）、与"跟随 VS Code"决策相悖

## 4. 组件改造清单

### 4.1 Manifest 层（`package.json`）

- 新增字段 `"l10n": "./l10n"`
- 换 `%key%` 的范围：18 个命令 title、activitybar 容器 title（"Commit"）、3 个视图 name（"Git Log" / "Worktrees" / "Commit"）、配置组 title、9 个配置项的 description 与 enumDescriptions
- 保持字面量不译：panel 容器 title "JetBrains Git Control"（品牌）、命令 category "JGC"（品牌缩写）、命令 id
- 注意：enumDescriptions 内 `#jgc.blame.aroundLines#` 之类设置交叉引用语法须原样保留在翻译字符串内
- 新建两个文件（key 命名约定 `jgc.<域>.<对象>.<字段>`）：
  - `package.nls.json`（英文基线）
  - `package.nls.zh-cn.json`（中文）

### 4.2 扩展主机层（`src/`）

- 包裹规则：**仅用户可见文案**用 `vscode.l10n.t()` 包裹
- 在范围内：39 处 `show*` 对话框调用的 message/labels、状态栏 tooltip（"Open IDEA Git Graph Panel"）、git 用户可见错误字面量（如 `"No changes to shelve"`，gitService.ts）、webview 代理默认值 `"OK"`（extension.ts:634）、shelf 名前缀 `"Clipboard patch"`（extension.ts:1484）
- 不在范围内：品牌（状态栏文字 `$(git-branch) IDEA Git`）、内部日志、异常匹配/控制流用字符串、git 原始输出（stderr 透传）
- 实现时逐文件审查 `src/**` 字符串字面量，防止漏包或误包

### 4.3 Webview 层（`webview/src/`）

- `webview/package.json` 新增运行时依赖 `@vscode/l10n`（约 2KB，无传递依赖负担）
- `main.tsx`：顶部同步 `config` + dev 模式守卫（见 §5）
- `vite-env.d.ts`：声明 `window.__L10N_BUNDLE__?: Record<string, string>`
- 45 个 `.tsx` 的全部用户可见文案包裹 `l10n.t()`：JSX 文本、`title=` / `placeholder=`、空态提示、按钮 label、tooltip
- webview → host 的对话框文案（`showInputBox` / `showConfirmMessage` 等 params）源头在 webview，**在 webview 侧包裹**即可，消息协议零改动
- 统一使用 **indexed 占位符 `{0}` / `{1}`**（中英两端机制均支持；不用 named 形式，避免两侧实现差异）
- 保持不译：4 个日期格式化 helper（`IdeaShelfTab` / `ShelfTab` / `CommitRow` / `CommitInfo`，维持 `yyyy-MM-dd HH:mm`，与 JetBrains 一致）、品牌词、命令 id

### 4.4 构建与打包

- esbuild 零改动（`vscode` 本就 external）；vite 仅多打包 `@vscode/l10n`
- `l10n/` 目录默认进 VSIX（`.vscodeignore` 无需改动）；`docs/**` 已排除，spec 不会进包

## 5. 边界与错误处理

| 场景 | 处理 |
|---|---|
| 缺翻译 | 官方机制回退：`l10n.t()` 未命中 key 返回英文源码，无报错。zh-cn 漏翻一条 = 该条显示英文 |
| 动态拼接 | **禁止拼接译文片段**，统一整句 + 占位符：`l10n.t("Failed to create patch: {0}", msg)`（中英语序不同，拼接必坏） |
| 计数复数 | 官方 bundle 无 ICU 复数规则；实现时排查 `N files` 类句式，改用 `{0} file(s)` 等中英兼容写法 |
| git 原始输出 | 透传不译；只包自产字面量 |
| Webview dev 模式（`pnpm run dev:web`） | 无宿主注入 → `config({ contents: window.__L10N_BUNDLE__ ?? {} })` 守卫，正常英文 |
| 歧义词给译者上下文 | "Shelve" "Discard" 等用 `l10n.t({ message, comment })` 附注 |
| 译文含 `</script>` 等特殊字符 | 注入前 `<` → `\u003c` 转义；不做 HTML 拼接（文本走 React 渲染） |

## 6. 提取与翻译工作流

```
① 代码改造（manifest %key% / host l10n.t / webview l10n.t）
② pnpm run l10n:export
   新增脚本: l10n-dev export --outDir ./l10n ./src ./webview/src
   产出 l10n/bundle.l10n.json（英文基线，提交仓库）
③ 翻译初稿（AI 辅助，术语按附录 A）:
   l10n/bundle.l10n.zh-cn.json + package.nls.json + package.nls.zh-cn.json
④ 人工审校 → 定稿提交
```

- devDependencies 新增 `@vscode/l10n-dev`（仅开发期使用）
- 每次代码新增文案后重跑 `l10n:export`，diff 即"漏包清单"
- 扩展新语言：新增 `bundle.l10n.<locale>.json` + `package.nls.<locale>.json`，零代码改动
- 首次提取后得出确切的文案条数（预估 300±）

## 7. 质量保障

### 7.1 自动校验（单测，`src/i18n/bundle-completeness.test.ts`）

走现有 `pnpm run test:unit`（`node --test`，无需 VS Code 实例）：

1. `bundle.l10n.json` 每个 key 均存在于 `bundle.l10n.zh-cn.json`（漏翻检测，兼容 `string | {message, comment}` 两种条目形态）
2. 反向检测 zh-cn 无陈旧 key（源已删除的残留）
3. `package.json` 全部 `%key%` 在 `package.nls.json` 与 `package.nls.zh-cn.json` 中均有定义
4. en / zh 的 `{0}`、`{1}` 占位符集合一致（防译文丢占位符）

### 7.2 验收门禁

`pnpm run check-types` + `pnpm run test:unit` + `node esbuild.js` + `pnpm run build:web` 全绿。

**规避 `pnpm run lint`**：本仓库存在约 92 条 CRLF 历史遗留误报（checkout 换行符所致，与本次改动无关），本次不作为门禁，也不借机改动。

### 7.3 人工冒烟

- 英文（默认）跑一遍全矩阵回归；切 `zh-cn`（`Configure Display Language`）重跑
- 矩阵：7 个 webview（panel / merge / conflicts / commit / push / rollback / worktree）、命令面板、设置页、状态栏、关键路径（提交、搁置 / 取消搁置、冲突解决、新建工作树、push）
- 可选：`l10n-dev generate-pseudo` 生成 `qps-ploc`，已包裹文案会变明显变形文本，一眼扫出漏网硬编码
- WSL 验证（宿主在 WSL 远程扩展主机，Windows `code` CLI 装不上）：
  1. `cd webview && pnpm install && pnpm run build`（产出 `dist/webview/assets/main.js` + `style.css`）
  2. `node esbuild.js --production`
  3. 打包：先 `npm pkg set 'scripts.vscode:prepublish=node esbuild.js --production'`（绕开 vsce 3.7.1 无 `--skip-prepublish` 且 prepublish 链到 lint 的陷阱），`npx vsce package --no-dependencies`，完成后 `git checkout -- package.json`
  4. 安装：`wsl.exe -e bash -lc '$(ls -d ~/.vscode-server/bin/*/ | tail -1)/bin/code-server --install-extension <path-to-vsix>/<name>.vsix'`
  5. 证明新构建生效：在安装后的 `dist/extension.js` 中 grep 本次唯一的**字符串字面量**（如 `bundle.l10n` 相关新字面量；生产构建已 minify，函数名/标识符 grep 无效）
  6. 注意：`webview/pnpm install` 会向 `webview/pnpm-workspace.yaml` 注入 `allowBuilds:` 占位符，验证后还原该文件；live reload 不可用（`/tmp/vscode-ipc-*.sock` 为空），需用户手动 `Developer: Reload Window`

### 7.4 风险

| 风险 | 缓解 |
|---|---|
| 漏包硬编码 | pseudo-locale 复核 + 实现期逐文件 grep 审计 + 提取 diff |
| 译文语序需重排 | 禁用拼接、统一占位符；审校覆盖 |
| 术语不一致 | 附录 A 术语表 + 人工审校定稿 |
| CRLF lint 干扰 | 明确不纳入门禁（§7.2） |
