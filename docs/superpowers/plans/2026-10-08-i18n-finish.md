# JGC i18n 收尾 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把已完成的 feat/i18n 实现与最新 main 合并、按 IDEA 官方中文修订术语、全量验证后开 PR 合回 main（Phase G）。

**Architecture:** 不新增任何机制。沿用既有"单一语言源（`webview/src/l10n/*.json`）→ `sync-nls.mjs` 派生"架构。本计划分三块：① 一次"双方都保"的冲突合并；② 数据文件（zh-cn.json）术语修订 + 合并面补译；③ 验证与 Phase G。

**Tech Stack:** git、pnpm、esbuild、vite、vitest、gh CLI

**Spec:** `docs/superpowers/specs/2026-10-08-i18n-finish-design.md`

## Global Constraints

- 冲突解决原则：**双方都保**（main 的功能改动 + i18n 的 `t()/tpl()` 本地化），禁止整文件取任一边
- 只改 `webview/src/l10n/zh-cn.json` 的中文值；`en.json` 仅允许一处值更新（`panel.searchPlaceholder`，Task 2）
- 品牌不译：JetBrains Git Control、JGC、IDEA Git、Git、VS Code、Shelf（tab 名）
- `pnpm run lint` 不纳入门禁（~92 条 CRLF 存量误报，checkout 换行符所致）
- 不 rebase、不 force-push（feat/i18n 已推送）
- 仓库流程：fork → 上游 PR —— 本地 `origin`=dunlingzi fork；上游 `witt-bit/jetbrains-version-control`（`upstream` remote，i18n 分支托管于 `upstream/feat/i18n`）；维护者习惯 **squash merge**（PR #4 先例）
- 进 PR 的所有内容（含 `docs/`）需脱敏：无真实客户项目路径/名称、无机器专属路径（用通用占位）
- 给上游的改动要过相关文件格式检查：`npx biome check <changed files>`（全量 lint 被 CRLF 阻塞时也要单独查）
- 提交信息用英文，conventional 风格
- 已确认复核点：A= Shelf tab 保留英文 "Shelf"；B= `gitService` 3 条自撰错误维持不译
